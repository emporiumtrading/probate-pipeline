# Fast desk: time-sensitive work between the daily runs

The main runner (session `session_01VKtpFDZbbd6DhTxHVpZuwn`) does the heavy work three times a day: sourcing, deep-dives, expansion, reports. The fast desk (session `session_01VKtpFAuYZcMNrX5sQ8wvgc`, on its own schedule) runs every 2 hours during business hours and does only what shouldn't wait for the next main run. It can act as **any** worker: for each item it reads that worker's role file (`agents/<worker>.md`) and works as that worker, so workers added later are covered with no change here.

Hard limits from `references/daily-run.md` → "Hard limits" apply exactly as in a main run. Nothing goes out without the Compliance Officer's gate, and outreach follows `autonomy` and each market's `attorney_approved`.

## Each firing, in this order
0. **Don't collide with the main run.** Read the main runner with `get_session` (`session_01VKtpFDZbbd6DhTxHVpZuwn`). If its status is working or running, end now with "Main run in progress; skipped." Otherwise `git checkout main && git pull --rebase origin main`.
1. **Is there anything to do?** Count: open or escalated items on the board (`python3 scripts/handoffs.py sweep`, then `check`); new owner decisions (step 3); new replies if the inbox channel works (`channels.inbox_connected: true`). If all are zero, end now with "Nothing waiting." and commit nothing. Most firings should end here and cost almost nothing.
2. **Clear the handoff board.** Take open items oldest-first, with urgent and blockers ahead of the rest, at most 15 per firing. For each one, read `agents/<to_worker>.md` and the lead's files, then do what that worker would do: answer with evidence, or reassign it with a reason. A request the size of a full deep-dive or a new market stays open for the main run; leave it as it is. Close answers to questions a worker asked once the answer is enough. Never act for `owner`.
3. **Owner decisions.** `db_whoami`, then for `outreach`, `sign` and `wire`: `db_list` `data/users/<id>/decisions/<queue>` on the dashboard, save each output, and run `python3 scripts/owner_decisions.py import <queue> <file>`. Act on every row with an empty `applied`, exactly as runbook step 1 describes (approved: compliance gate, then send if a channel works, or mark it print-ready; changes: redraft; rejected: Dead with the note; sign/wire done: record it). Set `applied` when done.
4. **Replies** (only when the inbox channel works). Collect new received emails (Resend), log them in `pipeline/inbox-log.csv`, and route each as `agents/communications.md` and `agents/reply-desk.md` say. A stop request goes on the stop list at once. Draft an answer into `leads/<id>/outreach-drafts.md`. A counter-offer becomes a handoff to `negotiator` (urgent). Send only what the autonomy rules allow; everything else waits for the owner on the Messages page.
5. **Save.** Run `python3 scripts/handoffs.py check`. Commit only the files this firing changed (`Fast desk YYYY-MM-DD HH:MM: N handoffs, M decisions, K replies`), then `git pull --rebase origin main` and push, retrying up to 3 times. On a rebase conflict in a file you didn't change, keep the other side. In one you did change, re-apply your small edit on top of the latest version.
6. **Dashboard** (only if step 2, 3 or 4 changed something). Run runbook step 7 as written: build into a scratch folder, `qa_checks.py` and `check_page.py` must pass, upload every CSV (plus `messages.json` only while the dashboard is private), and update the datasets with `ifVersion`. Use only the allow-listed dashboard tools. If anything fails, skip the dashboard; the next main run refreshes it.
7. **End** with one short line: handoffs cleared, decisions applied, replies handled, anything escalated to the owner.

## What the fast desk never does
Sourcing, deep-dives of new leads, market expansion, legal refresh, the daily report, or the weekly calibration: those stay with the main runner. It never edits `config.yaml`, the role files or the runbook (learning goes through the main run's step 7b). It also never starts a second firing while one is running.
