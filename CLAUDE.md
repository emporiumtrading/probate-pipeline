# Probate Pipeline

Private working repo for a multi-state probate real-estate wholesaling pipeline. Live and queued markets are listed in `config.yaml` (markets + expansion_queue, covering all 50 states + DC).

- The skill lives in `.claude/skills/probate-wholesale-deal/`. For the scheduled daily run, follow `.claude/skills/probate-wholesale-deal/references/daily-run.md` exactly.
- Runner (owner decision 2026-11-25): the scheduled slices A/B/C and the fast desk run as Render cron jobs (`render.yaml`, `runner/run.mjs`, `scripts/auto_slice.py`, engines tried in order: Claude, then NVIDIA, then OpenRouter free models, each able to run the whole slice, then the scripted run with no AI; owner decisions 2026-11-25: fully autonomous and dynamic). Each run measures the waiting work (`runner/workload.py`), picks the model itself (no AI when nothing waits, Haiku for routine work, Sonnet for deep-dives, negotiation and repairs, capped by the owner's setting) and moves up a model when an attempt fails or its result fails `qa_checks.py`. A run that follows a failure starts with `references/self-repair.md`. Runs can never change the guardrails: the runner undoes any change its own commits make to the Hard limits, the QA and page checks, `guardrails.sha256`, `runner/`, `render.yaml`, CLAUDE.md or the role files. After each push the runner deploys what changed on Render (`runner/deploy.mjs`). Keys and the Claude model cap are set on the dashboard's Setup page → AI engines, which saves keys only as Render env vars, never in git. The **Full autonomy** switch (top of the dashboard) turns on only after `web/preflight.js` finds nothing missing; while it is on, runs follow `references/full-autonomy.md` and the owner hears only about signatures, escrow confirmations, confirmed deposits and closings with profit, plus at most one email a day if the system itself stays broken for 24 hours despite the automatic repairs (`runner/notify.py`; owner decision 2026-11-26). The web app is `probate-dashboard` on Render behind the Emporium Investments admin login, at `app.emporium-investments.com`; `www.emporium-investments.com` (and the bare domain) show the public company page `web/site.html` from the same service (owner decision 2026-11-27; `runner/deploy.mjs` adds the domains on Render). The claude.ai scheduled tasks below are paused so only one runner works the pipeline; a Claude session is used for work the scripts can't do (letters, negotiation, attorney matters, Stripe import, the claude.ai dashboard).
- Earlier setup (owner decisions, 2026-11-21, now paused): the runner session `session_01VKtpFDZbbd6DhTxHVpZuwn` runs the scheduled daily slices and refreshes dashboard data. The fast desk session `session_01VKtpFAuYZcMNrX5sQ8wvgc` (see `.claude/skills/probate-wholesale-deal/references/fast-desk.md`; schedule: 8:47, 10:47, 14:47, 16:47, 19:47 Central) runs every 2 hours in business hours for time-sensitive work only: the handoff board for any worker, owner decisions, replies. It skips any firing while the main run is working. Any other session (including the setup session) makes design or setup changes only when the owner asks, and doesn't run pipeline slices or write dashboard datasets on its own. Every session pulls before working and pushes with rebase, never force.
- Orchestrator (owner decision 2026-11-25): **Hermes** (Nous Research Hermes Agent, Render service `probate-hermes`, built from `hermes/`). The owner chats with it in a floating chat window over the dashboard (the Probate AI Assistant button, bottom right; it confirms every task the owner gives it, `/api/hermes/tasks`, and directs the workers through the handoff board as `hermes`, by the profit-and-growth rules in its SOUL; `web/hermes-ui.js` → `/api/hermes/chat` → Hermes's OpenAI-compatible API). It works on a clone of this repo as a full operator, holding only its AI keys and the GitHub token (it reaches Render and the database only through the dashboard's narrow, rate-limited `/api/ops` door, `web/ops-api.js` → `pipeline-ops`; no Render key, database password or sending keys): answers questions, starts runs through the Render API, works the task board as any worker, fixes problems and improves code and worker instructions, and supervises the pipeline every hour. Its rules are `hermes/SOUL.md`. It never changes the guardrails: every run undoes any change Hermes's commits make to the protected files (`runner/run.mjs` → `HERMES_PROTECTED`), and `qa_checks.py` fails on any guardrail change without the owner's approval.
- Database (owner decision 2026-11-25): Render Postgres `probate-db` (private, Render services only). After every run `runner/dbsync.mjs` copies every `pipeline/**.csv` row, the lead files, reports, legal notes, `config.yaml` and the owner's dashboard saves into it, with a full change history (`records`/`record_history`, `files`/`file_history`, `store_docs`/`store_history`, `sync_runs`; views `leads`, `ledger`, `runs`). Each run also publishes the dashboard datasets it built and checked (`qa_checks.py` passed) into `dashboard_data`; the website reads `/data/*` live from there (`web/db.js`, 15-second cache) and falls back to the files built at deploy. The repo stays the source of truth for code, instructions and records; workers' bulky working data lives in the database's `work_cache` table (`workcache/`, restored and saved by the runner, `runner/workcache.mjs`). Never put API keys in the database.
- Settings: `config.yaml` (autonomy, targets, markets). Pipeline: `pipeline/deal-tracker.csv`. Per-lead files: `leads/<lead_id>/`. Daily reports: `reports/`. State legal notes: `legal/`. Attorney/title shortlists: `network/`.
- Dashboard data is built only by `scripts/build_dashboard_data.py` and must pass `scripts/qa_checks.py` before publishing. The page source is `dashboard/index.html`.
- Contact rules come from `config.yaml` → `autonomy` and the Compliance Officer. Outreach is `autonomous` (owner decision 2026-11-25), but a market sends only with `attorney_approved: <date>`, a tested sending channel, the Compliance PASS and the 90-day wait after death; until then its letters wait as held drafts. Workers decide routine matters within written limits and log them in `pipeline/decisions-log.csv`; the owner only signs and confirms earnest-money deposits. New workers start in trial (shadow mode) per `references/worker-lifecycle.md`. Never phone or text automatically, never sign for the owner personally (the company's own e-signature may sign only inside `config.yaml` → `company_signature` once `scripts/sign_check.py` passes), never handle bank details or emailed wiring instructions. Earnest money: ask for $0 first, then the minimum, only refundable, only inside the reserve (`scripts/reserve.py`: $1,000 to start, refilled at each closing with the deal's deposit plus 25% of its profit).
